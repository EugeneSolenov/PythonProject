# Семейный календарь — Веб-приложение на Django (ПР5, ПР6, ПР7)

Индивидуальный сквозной учебный проект по дисциплине «Технологии разработки приложений на базе фреймворков».
Проект представляет собой менеджер персональных и семейных событий, напоминаний и памятных дат с консольным интерфейсом (ПР1–ПР3), веб-интерфейсом на базе Django с шаблонами DTL (ПР5 и ПР6) и слоем реляционной базы данных SQLite с SQL-запросами (ПР7).

---

## 1. Назначение проекта

«Семейный календарь» — приложение для учёта важных дат, семейных праздников, учебных дедлайнов и повседневных дел нескольких пользователей.
Проект развивается поэтапно:
- **ПР1–ПР3**: консольное приложение, модульная структура, объектная модель (`Event`, `User`), хранение данных в JSON, автоматические тесты;
- **ПР5**: добавление веб-слоя на Django: HTTP-запросы/ответы, трехуровневая маршрутизация URL, view-функции, обработка ошибок 404, подключение Bootstrap;
- **ПР6**: полноценный перевод веб-интерфейса на **Django Template Language (DTL)**: базовый шаблон, наследование, включаемые компоненты (`{% include %}`), пространства имён URL, фильтры шаблонов, передача контекста, собственные статические файлы (CSS, JS, логотип);
- **ПР7**: внедрение слоя реляционной базы данных **SQLite**: проектирование таблиц, первичных и внешних ключей (`FOREIGN KEY`), модуль подключения `db/database.py` с контролем ссылочной целостности (`PRAGMA foreign_keys = ON`), скрипт импорта данных `db/import_json.py`, разработка 12 SQL-запросов (`sql/queries.sql`), параметризованный поиск по дате и страница статистики на основе SQL-агрегатов и группировок.

## 3. Слой реляционной базы данных (ПР7)

### 3.1. Структура таблиц базы данных

База данных проекта хранится в файле `data/calendar.sqlite` и содержит три связанные сущности:

1. **Таблица `categories` (Категории событий)**:
   | Поле | Тип | Назначение |
   | :--- | :--- | :--- |
   | `id` | `INTEGER PRIMARY KEY` | Уникальный идентификатор категории |
   | `name` | `TEXT NOT NULL UNIQUE` | Название категории («Праздники», «Учёба» и др.) |
   | `description` | `TEXT` | Подробное описание назначения категории |
   | `icon` | `TEXT NOT NULL DEFAULT '📅'` | Эмодзи/иконка категории |

2. **Таблица `users` (Члены семьи / Пользователи)**:
   | Поле | Тип | Назначение |
   | :--- | :--- | :--- |
   | `id` | `INTEGER PRIMARY KEY` | Уникальный идентификатор пользователя |
   | `name` | `TEXT NOT NULL` | Имя члена семьи |
   | `email` | `TEXT NOT NULL UNIQUE` | Электронная почта |

3. **Таблица `events` (События семейного календаря)**:
   | Поле | Тип | Назначение |
   | :--- | :--- | :--- |
   | `id` | `INTEGER PRIMARY KEY` | Уникальный идентификатор события |
   | `user_id` | `INTEGER NOT NULL` | Внешний ключ: `REFERENCES users(id) ON DELETE CASCADE` |
   | `category_id` | `INTEGER NOT NULL` | Внешний ключ: `REFERENCES categories(id) ON DELETE RESTRICT` |
   | `name` | `TEXT NOT NULL` | Название мероприятия/события |
   | `event_date` | `TEXT NOT NULL` | Дата события в формате `YYYY-MM-DD` |
   | `is_completed` | `INTEGER NOT NULL DEFAULT 0` | Признак завершения (0 — актуально, 1 — выполнено) |

### 3.2. Файлы и модули базы данных

- **`sql/schema.sql`** — DDL-скрипт создания структуры таблиц и внешних ключей;
- **`sql/queries.sql`** — коллекция из 12 проверенных SQL-запросов (выборка, фильтрация WHERE, соединение JOIN, агрегаты COUNT/SUM/MIN/MAX, группировка GROUP BY, фильтрация групп HAVING, подзапросы NOT IN);
- **`db/database.py`** — модуль подключения к SQLite с обязательным включением проверки внешних ключей (`PRAGMA foreign_keys = ON`) и настройкой `row_factory = sqlite3.Row` для именованного доступа к полям;
- **`db/import_json.py`** — модуль переноса данных из исходных JSON-файлов (`categories.json`, `users.json`, `events.json`) в таблицы SQLite с нормализацией дат и сохранением целостности связей.

## 5. Пользовательские сценарии и маршруты веб-приложения

1. **Главная страница (`/`)** — `homepage:index`:
   - Отображает агрегированную сводку из SQLite: общее число событий, количество предстоящих и выполненных дел, общее число категорий, а также три ближайших события.
2. **Список всех событий (`/events/`)** — `events:list`:
   - Выводит события, отсортированные по дате; для каждого события отображаются категория, дата, статус и ответственный член семьи (результат соединения трёх таблиц через `JOIN`).
3. **Поиск событий по дате (`/events/search/`)** — `events:search`:
   - Форма с выбором даты; выполняет параметризованный SQL-запрос `WHERE events.event_date = ?` и возвращает запланированные на день дела.
4. **Статистика семейного календаря (`/events/statistics/`)** — `events:statistics`:
   - Сводные аналитические показатели: общее число событий, распределение событий по категориям (`LEFT JOIN + GROUP BY`), распределение по членам семьи, популярные категории с количеством событий более одного (`GROUP BY + HAVING`).
5. **Карточка события (`/events/<id>/`)** — `events:detail`:
   - Полные сведения о событии, ответственный пользователь, email, количество оставшихся дней и статус выполнения.
6. **Список категорий (`/categories/`)** — `categories:list`:
   - Карточки категорий с подсчётом привязанных событий через `LEFT JOIN ... GROUP BY`.
7. **Детальная страница категории (`/categories/<id>/`)** — `categories:detail`:
   - Описание категории и список всех относящихся к ней событий.

## 6. Запуск и проверка проекта

### Запуск веб-сервера Django:
```bash
python manage.py runserver
```
Веб-интерфейс доступен в браузере по адресу: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)

### Пересоздание и повторный импорт базы данных SQLite:
```bash
python db/import_json.py
```

### Проверка конфигурации Django:
```bash
python manage.py check
```

### Запуск автоматических тестов (pytest):
```bash
pytest -v
```
Все **31 тест** (логика консольного сценария, модели, целостность SQLite, внешние ключи, SQL-запросы, веб-маршруты и шаблоны) выполняются успешно.

### Проверка стиля кода (flake8):
```bash
flake8 . --extend-exclude=venv
```
Код на 100% соответствует стандарту PEP 8 (без предупреждений и замечаний).

### Генерация отчётов:
```bash
python reports/create_reports.py
```
Формирует актуальные docx-отчёты в каталоге `reports/`, включая `Отчет_ПР7_Соленов.docx`.
